# Directives

Generated by `quicksql directives --markdown` from quicksql's builtins. A notebook
with plugins of its own (a `quicksqlrc.py` next to it, or `--plugins`) can write more:
`quicksql directives NOTEBOOK` lists exactly what that notebook can write.

Write a directive as a comment: `-- @key: value` on one line, or YAML in a
`/*@ ... */` block. Values are literal YAML; only the SQL body is Jinja.

- **Scope**: `global` goes in the header (before the first `@cell`), `cell` in a cell,
  `both` in either; a cell's value applies over the header's.
- **Merge**: how a cell's value combines with the header's and with `--set`
  overrides: `override` replaces it, `deep` merges mappings key by key, `extend`
  appends to the list.
- **Reruns**: whether editing it changes the cell's fingerprint, so a save reruns the
  cell and `status` calls its output stale.

| Directive | Scope | Type | Default | Merge | Reruns | What it does |
|---|---|---|---|---|---|---|
| `autorun` | both | boolean | `true` | override | no | Whether a save reruns the cell when it changed (watch, an armed TUI); `false` leaves it to explicit runs. |
| `catalog` | global | mapping | `{}` | deep | no | More targets for the TUI's schema browser, by engine: `{postgres: [dsn], bigquery: [project.dataset], duckdb: [path.db]}`. |
| `depends_on` | cell | list of strings | `[]` | extend | yes | Upstream cells to run first besides those `ref()` records, e.g. an effect-only cell this one needs. |
| `engine` | both | string or null | `null` | override | yes | Run the cell on this engine (duckdb, sqlite, postgres, bigquery); usually inferred from `input`. |
| `extensions` | both | list of strings | `[]` | extend | yes | DuckDB extensions to load before the cell runs, e.g. `[httpfs, spatial]` (the cell must run on duckdb). |
| `input` | both | mapping | `{}` | deep | yes | Where the engine connects, keyed by engine (its one key picks the engine): `{duckdb: path.db}`, `{sqlite: path.db}`, `{postgres: {dsn: $PG_DSN}}`, `{bigquery: {project: ..., endpoint: ...}}`. |
| `output` | both | mapping | `{type: parquet, dir: data/}` | deep | yes | Where the result lands (the sink): `{type: parquet, dir: data/}`, `{type: duckdb, path: warehouse.db, table: ..., schema: ..., mode: append}`, `{type: postgres, dsn: ..., table: schema.name}`, or `{type: none}` (effect-only: lands nothing, can't be `ref()`'d). |
| `render_dir` | global | string or null | `null` | override | no | Write each cell's rendered SQL into this directory before it runs. |
| `schema` | both | string or null | `null` | override | yes | The schema a database sink lands in, unless `output.schema` names one. |
| `sources` | both | mapping | `{}` | deep | yes | Named files that `source('name')` reads: `{name: path}`, or `{name: {path: ..., type: csv, ...reader options}}` (csv, parquet, json, excel). |
| `tags` | both | list of strings | `[]` | extend | no | Free-form labels. |
| `vars` | both | mapping | `{}` | deep | yes | Values the SQL reads with `var('key')` (or `vars.key`); override one with `--set vars.key=value`. |

## Engines `engine:` can name

| Engine | SQL dialect | `input` shorthand |
|---|---|---|
| `duckdb` | duckdb | `{duckdb: <path>}` |
| `sqlite` | sqlite | `{sqlite: <path>}` |
| `bigquery` | bigquery | `{bigquery: <project>}` |
| `postgres` | postgres | `{postgres: <dsn>}` |

## Sinks `output.type` can name

| Sink | Lands an output | What it is |
|---|---|---|
| `parquet` | yes | Default sink: one parquet file per cell in output dir (default data/). |
| `duckdb` | yes | Sink into a DuckDB database file, ATTACHed onto the conduit connection. |
| `postgres` | yes | Sink into Postgres through DuckDB's postgres extension (ATTACH ... TYPE postgres). |
| `none` | no | Effect-only sink: the cell runs for its side effects and lands nothing. |
